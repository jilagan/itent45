The three tiers of a web application

In a restaurant, the customer never walks into the kitchen. The customer tells a waiter what they want, the waiter goes to the kitchen, collects the food and brings it back. A web application is divided in the same way. The customer is the browser, the waiter is the application server, and the kitchen is the database. Each of these three parts is called a tier. AI tools can write much of this code for you, but you still need to know where each tier runs and what passes between them. Two tiers run on servers you manage. The third runs on your user's own device, which you do not control.

Think first Pick any part of a page you use every day, such as the list of courses you enrolled in. Which tier produced it: the browser, the application server or the database? Write down your answer, then check it against the steps below.

Why the browser cannot talk to the database directly Suppose it could. The database password would then have to be stored in code running on the user's laptop. Anyone could read it and run any query they liked. In the restaurant, that would be a customer walking into the kitchen and helping themselves. The application tier is the only part that holds the database password, and it decides which requests are allowed.
