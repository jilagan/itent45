Backpropagation

Suppose a dish is sent back to the kitchen because it is too salty. Several people handled it before it reached the customer. To decide who should change what they do, you start from the complaint and work backward through each person, asking how much that person's work affected the result. A neural network needs the same kind of trace. A weight is a number that sets how strongly one input counts, and a slope tells you how much the loss would change if that weight were nudged up a little. In the panel "Training: adjusting a model to reduce its errors", each of the three numbers touched the answer directly, so finding its slope took one step of arithmetic. With hidden units that shortcut stops working, because a weight in the middle affects the answer only through the units after it. The method that solves this is called backpropagation.

Think first. Suppose the sauce station uses a little less salt. How much would the customer's complaint change? What would you need to know about the steps after the sauce station to answer?
What is happening
What the name means In the forward pass, each layer hands its answer to the next layer. In the backward pass, each layer hands its share of the blame to the layer behind it. Backpropagation means propagating, or passing along, the error backward.

The rule underneath is called the chain rule. You can use the idea without the formula: to know how much a weight mattered, multiply how much its output mattered by how much the weight affected that output.
Why backpropagation is cheap Look at the numbers as they appear. Each one is built from a number that was already worked out one step earlier. Nothing is computed twice, and nothing is computed from scratch.

The alternative is to nudge each weight a little, run the whole network again, and see whether the loss improved. That works, and for a network with a billion weights it means a billion full runs to make one step. Backpropagation gets every slope in one backward pass, which costs about the same as one forward pass.

The idea was published in 1986 and the arithmetic has not changed since. Hardware improved later, and then the amount of text available to train on grew.
What you can skip You can skip the derivation, the notation and the proof that the method is correct. You will not implement this, because every machine learning library does it for you. It is still worth a few minutes. One common cause of a training run that produces nothing is that the blame stopped flowing backward somewhere, and people describe that problem in these words.
