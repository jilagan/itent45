AI, machine learning, deep learning and generative AI

A calculator gives the right change because someone wrote the rules of arithmetic into it. A new cashier learns to spot a fake bill by handling thousands of bills, and nobody writes down the rule. Both are useful, and they get there in different ways. That difference separates four terms that people often use as if they meant the same thing: artificial intelligence (AI), machine learning, deep learning and generative AI. Each one sits inside the one before it.

Knowing which term fits a system tells you how it was built and how it tends to fail.

Think first. A chess program beat the world champion in 1997. Would you call it artificial intelligence? Did it learn from the games it played? Decide on your answers, then check them against the chess example below.
Ask for a show of hands on both questions before students open the chess example. Most will say yes to AI and split on learning. The rule-based case matters most for the rest of the module, because later panels assume students can tell a learned model from a hand-written program.

Choose a system
Two of these systems are AI that does no machine learning at all. Many people forget that this kind exists.

Here are the four terms from the outside in. Three terms need defining first. A feature is one measurement that a person decides to feed the program, such as the number of links in an email. Labeled data means examples that come with the right answer attached, such as emails already marked spam or not spam. An algorithm is a fixed set of steps for solving a problem.

Outermost
Artificial intelligence

Any program that does something we would call intelligent if a person did it, such as searching, planning, following rules or reasoning with logic. Most of it was written by hand, learns nothing, and is decades old.

chess engines · route finding · scheduling
Inside that
Machine learning

Programs that work out their own rule from examples. Nobody writes the rule down. People supply a million emails already labeled spam or not spam, and the program finds the dividing line between the two groups itself.

spam filters · credit scoring · recommendations
Inside that
Deep learning

Machine learning built from many stacked layers. The layers work out for themselves what is worth measuring, so a person no longer chooses the features. You give it the raw input, such as pixels or sound.

face recognition · speech to text · translation
Innermost
Generative AI

Systems that produce new content, such as a paragraph, an image or a working function. A spam filter gives one of two answers, spam or not spam. A generative system writes out something that did not exist before.

language models · image models · coding assistants
Three points to keep in mind AI is not new. The term was coined in 1956. What changed recently is the small innermost circle in the diagram.

Most AI does not learn. A great deal of what runs your bank, your airline and your traffic lights is rules that people wrote. It works, and nobody markets it as AI any more.

When a product says "AI" today, it usually means the innermost circle. Ask which kind it is, because the four fail in different ways. A rule that is wrong is wrong the same way every time. A model that is wrong is wrong in a way that depends on the examples it was trained on.

The rest of this module is about the innermost circle. It covers what the model predicts, how it is trained, what it reads, and what happens when you give it tools.

How a language model writes: predicting the next word

When you type a message on your phone, the keyboard suggests the next word. It has not understood your message. It has learned which words usually follow the ones you typed. A language model is a program trained on huge amounts of text, and it works on the same idea at a much larger scale.

Every answer it gives comes from one repeated step. The model reads all the text so far, which is called the context. It works out a probability for every word that could come next, where a probability is a number from 0 to 1 that says how likely that word is. It picks one word and repeats the step. The model does not write a draft and revise it, and no separate step checks whether the sentence is true.

This panel shows one step, then the same step repeated to write an answer.

Think first. A model has read the words "The capital of France is". Guess how much of the probability it gives to its top word: about 30 percent, about 60 percent or about 90 percent. Then check the first prompt in the widget below.
Collect guesses before students open the widget. Most pick 90 percent or more, and the widget shows 89 percent. The distinction between recalling a fact and continuing a pattern comes up again in the code example below.

This section shows one step. The model gives a probability for every candidate word, and then one word is picked. The list of probabilities for all candidates is called a probability distribution. The first two prompts are sentences. The third is the start of a line of Python code that looks up a user in a database. The model has to choose between two database commands, get and filter.

Temperature setting
Temperature controls how far down the list the model is willing to reach. At 0 it takes the top word every time. At 1 it picks at random, in proportion to the percentages shown. Picking at random in proportion to the percentages is called sampling.

Press "Do it ten times" at temperature 0, then again at 1.2, and compare the two tallies.
Temperature 0 gives the most likely word, which can still be wrong At temperature 0 the model takes the most likely word each time. If that top word is wrong, you get the same wrong answer every time you ask, worded the same way and equally confident. That is harder to spot than an answer that changes from run to run.

A full answer is the same step repeated. The model takes the word it picked, adds it to the end of the prompt, and asks the same question again. A long answer of perhaps eight hundred words is built this way, one chosen word at a time. A model that works this way is called generative, because it produces new text.

What changes in the loop
After the first word, the model reads its own output as part of the prompt. By the time the next word is chosen, the words it wrote are treated the same way as the words you wrote.

The model never goes back. Once a word is added, every later word is chosen with that word already in place. The model does not reconsider a sentence it has started.
Why one early error can run through a whole answer If the model picks a slightly wrong word early, every word after it is chosen to fit that word. The result reads smoothly to the end, because each word is chosen to be a likely continuation of the text before it.
Generative models and classifiers In "Training and test data", the boundary answered a closed question: which side is this student on? The answer was one choice from a set that existed before the model ran, and nothing new was made. A program that sorts inputs into fixed categories like this is called a classifier.

The model in this panel answers an open question. The set of possible answers is every sequence of words there is. The word generative refers to this open set. A generative model's output can be fluent, new and wrong at the same time. A classifier can only be wrong in the ways its fixed set of answers allows.
Image generators work differently Image generators mostly start from random dots, called noise, and remove the noise in steps until a picture is left. That process is different from predicting words, and it fails in different ways. What you learn here about words does not explain why a generated hand has six fingers.
Students tend to assume that one mechanism sits behind every AI tool. Say out loud that this panel applies to language models only.

Training data and test data

Suppose you were given the exam paper a week early and memorized every answer. A model faces a similar problem, because it is built from examples and then has to be judged on how well it works.

The simplest useful model is a boundary. You collect examples of something that already happened, such as which students finished a course, and find a line that separates one outcome from the other. Nobody writes the line down. It starts in a poor position and is adjusted until it makes fewer mistakes. Adjusting a model to match examples is called fitting it, and the final line is the model.

This panel fits a line to some students and then tests it on students the line has not seen.

What is happening
What this kind of model is called A straight boundary fitted to labeled examples is called logistic regression. The name confuses many people, because regression usually means predicting a number, and this model predicts a category.

Linear regression draws a line through the points to predict a value. Given the hours a student studied, what mark will the student get? The answer is a number, and the line runs among the data points.

Logistic regression, which is what you have here, draws a line between the points to predict a group, such as pass or fail. On screen both are a line. The first answers "how much?" and the second answers "which group?". The later panels use the second kind.

A model that has seen every answer can remember them, and from the inside remembering looks the same as learning. Two terms describe how to guard against memorizing.

Training set

The part of the data that the model is allowed to see while it is being fitted. Every adjustment is made to reduce mistakes on these examples, so a good score here is expected and means little on its own.

Test set

The part you set aside before you started and never looked at. It stands in for the people the model has not met yet. Report this score as the model's result.

Split the data before fitting, and only once If you look at the test set, adjust something and try again, you have quietly trained on it. It is no longer a test, and you have no honest score left. This mistake is called leakage, because information from the test set leaks into the model. People make it often without noticing, and results that looked strong during development then fall apart in front of real users.

The gap between the two scores tells you what happened. A small gap means the model found the general shape of the data. A large gap means the model memorized its examples, which is called overfitting. The bent line in the section "Setting data aside and testing" shows this directly.

Training: adjusting a model to reduce its errors

Suppose you are standing on a hillside in thick fog and want to reach the bottom. You cannot see the bottom, but you can feel which way the ground slopes under your feet. So you take a step downhill, feel the slope again, and repeat.

Training a model follows the same routine. Start with a line placed at random. Measure how wrong it is with a single number called the loss. Nudge the line in whichever direction makes the loss smaller, and repeat a few hundred times. The fog stands for the fact that the program never sees the best line in advance and only measures the slope where it is standing.

The panel "Training and test data" used a boundary line without showing where it came from. This panel shows how the line is found.

The terms on this screen Loss, cross-entropy and gradient descent are the standard terms for this process. Here is what each one means on this screen.

Loss is the number in the first box. It is one score for how wrong the line is across all of the students. Lower is better.

Cross-entropy is the formula that produces the loss. It gives a large penalty when the model is confident and wrong.

Gradient descent is the routine of working out the slope of the loss for each of the three numbers the model adjusts, and moving each one a small step downhill.
Three numbers to adjust This line has a weight for hours, a weight for attendance, and a bias. A weight sets how much one measurement counts, and the bias moves the line up or down. Training adjusts those three numbers. A large language model does the same kind of adjusting to hundreds of billions of numbers, for months, on thousands of machines. The arithmetic is similar, and the cost is far larger.
Choosing the learning rate The learning rate is the size of each step, and somebody has to choose it. If it is too small, training crawls, and you pay for computing power that is barely moving the line. If it is too large, the line jumps past the bottom and ends up on the other side, over and over, and the loss goes up when it should go down. Nothing detects this for you. It is the most common reason a training run produces nothing, and it is the setting beginners change most often.

Select the largest setting and watch the loss curve go up.

Neural networks: combining several lines

Suppose a scholarship committee has several members. Each member applies one simple cut-off, such as at least 10 hours of study a week or at least 70 percent attendance. One cut-off is crude. The committee accepts a student only when every member agrees, and together the cut-offs can describe a shape that no single cut-off can.

A neural network works in a similar way. Each simple cut is called a unit, and later units combine the answers of earlier ones. In a real network the cuts are slanted lines found by training. In this panel the combining rule is fixed: the output says "stays" only when every unit agrees.

"How training works" found one line, and it worked because passing becomes more likely with more hours and better attendance. Not every question has that shape. This panel uses one that does not: who drops the course. Students drop when they are barely engaged, and they also drop when they carry far too much. The students in the middle stay.

Think first. Picture a plot with hours studied across the bottom and other commitments up the side. The students who stay are in the middle, and the students who drop surround them. Could one straight line put every student who stays on one side and every student who drops on the other? If you could use several straight lines and a rule for combining them, how would you place them?

The diagram and the plot Most people meet neural networks as a diagram of circles and arrows, and many never see what the network does. The diagram shows the wiring: which number is multiplied by which weight and passed on to where. A weight is a number that sets how strongly one input counts.

The plot shows the effect: what that wiring does to the space of possible students. One circle in the middle row is one line on the plot. Four circles make four lines. Both pictures are correct. The diagram shows what is connected, and the plot shows what those connections produce. Seeing only the diagram can make a network look more mysterious than it is.
Where the terms come from One line fitted to data is logistic regression, which is what "Training and test data" and "How training works" covered. Once you use several lines and combine their answers, you have a neural network with one hidden layer.

The vocabulary maps onto what is on screen. Each line is a unit, sometimes called a neuron. The set of units is a layer. The step that takes their answers and produces one verdict is the output unit, and here it says stays only when every line agrees.

The layer is called hidden because you never see what its units decided. You gave the network two numbers and read one answer. Whatever the units settled on in between is not shown to you, and nobody chose it by hand.
Features before and after deep learning

A feature is a measurement that the model uses as input.

Before deep learning

A person picked the features. To spot a likely dropout, an analyst would decide what to measure: hours studied, attendance, or whether the student had missed two submissions in a row. Getting those right was the main job, and it needed someone who knew the subject area. When the model failed, you could point at the feature that was wrong.

After deep learning

You give the network raw input and enough units, and its early layers work out their own features. In an image model, the first layers end up finding edges, later layers find shapes, and later still layers find faces. Nobody told the network to look for edges. Edges turned out to be the most useful thing for those layers to detect.

The cost: nobody can say what each unit means You no longer know what the features are. The few numbers on this screen can still be read. A real model has billions of numbers, and no single one of them means anything on its own. So a model can be excellent and impossible to explain at the same time, and when it goes wrong there is often nothing to point at.

Keep this in mind for the question of where meaning comes from, covered later in "Word embeddings". The same property that lets a model find features nobody named also lets it pick up patterns nobody intended.

Backpropagation

Suppose a dish is sent back to the kitchen because it is too salty. Several people handled it before it reached the customer. To decide who should change what they do, you start from the complaint and work backward through each person, asking how much that person's work affected the result.

A neural network needs the same kind of trace. A weight is a number that sets how strongly one input counts, and a slope tells you how much the loss would change if that weight were nudged up a little. In "How training works", each of the three numbers touched the answer directly, so finding its slope took one step of arithmetic. With hidden units that shortcut stops working, because a weight in the middle affects the answer only through the units after it.

The method that solves this is called backpropagation. This panel traces it through a small network.

Think first. Suppose the sauce station uses a little less salt. How much would the customer's complaint change? What would you need to know about the steps after the sauce station to answer?
What is happening
What the name means In the forward pass, each layer hands its answer to the next layer. In the backward pass, each layer hands its share of the blame to the layer behind it. Backpropagation means propagating, or passing along, the error backward.

The rule underneath is called the chain rule. You can use the idea without the formula: to know how much a weight mattered, multiply how much its output mattered by how much the weight affected that output.
Why backpropagation is cheap Look at the numbers as they appear. Each one is built from a number that was already worked out one step earlier. Nothing is computed twice, and nothing is computed from scratch.

The alternative is to nudge each weight a little, run the whole network again, and see whether the loss improved. That works, and for a network with a billion weights it means a billion full runs to make one step. Backpropagation gets every slope in one backward pass, which costs about the same as one forward pass.

The idea was published in 1986 and the arithmetic has not changed since. Hardware improved later, and then the amount of text available to train on grew.
What you can skip You can skip the derivation, the notation and the proof that the method is correct. You will not implement this, because every machine learning library does it for you. One common cause of a training run that produces nothing is that the blame stopped flowing backward somewhere, and people describe that problem in these words.

Tokens: how text is fed to a model

A child sounding out a long word reads it in pieces, such as con-ver-sa-tion. The pieces vary in length, and the child does not stop to look at each letter inside a piece. A language model reads text in pieces too: a whole word, part of a word, or a punctuation mark. These pieces are called tokens.

A program called a tokenizer cuts your text into tokens before the model sees anything, and each token is replaced by a number. The model works with those numbers and does not see the individual letters inside a token. The tokenizer chooses its pieces from text that turned up often in the material it was built from.

Word embeddings: how words get positions

At a barkada party, nobody hands out seat numbers, yet people who keep talking to each other end up sitting together. Word positions are found in a similar way. Every word starts at a random spot on a map. The program then reads sentences one at a time, and each sentence moves the words in it a little closer together while all other words drift slightly apart.

Each sentence moves the words by a small, fixed step, so no word chooses where it goes. The set of sentences used is called a corpus. The position a word ends up with is called its embedding. Here the map has two directions, called dimensions, so each embedding is two numbers. Real models use hundreds of numbers per word.

This panel shows how words get their positions. Using those positions is covered later in "Vectors and similarity".

Vectors and similarity of meaning

On a map, two pins that are close together mark places that are near each other. Words can be treated the same way. A token is only an ID number, and an ID number carries no meaning, so each token is converted into a vector: a list of numbers that gives the word a position.

Real models use a few hundred numbers per word, so their map has a few hundred directions. This list of numbers is the word's embedding. Words that appear in similar company end up in similar places, as "Word embeddings" showed. Nobody labels the words.

A model reflects the text it was built from. A prompt cannot remove that, because it is built into the positions the model uses. Anyone who claims a single tidy number for how biased a model is should be asked how they measured it.
Both statements hold, and students tend to keep only one of them: embeddings do absorb the statistics of their corpus, and the famous analogies overstate how cleanly that shows up.

Recurrent networks: the approach before transformers

Imagine sitting through a long lecture with a single sticky note. After each sentence you rewrite the note to summarize everything so far, and then you forget the sentence. At the end you can answer questions only from the note.

Until about 2017, language models read text this way. They are called recurrent neural networks. The model reads left to right. After each word it updates one small note, called the hidden state, that summarizes everything read so far, and then it moves on without the word. The note is a fixed size, so each new word pushes something older out.

This panel shows the problems that causes. The fix is covered later in "Attention and transformers".

Think first. In the sentence The animal didn't cross the street because it was too tired, what does it refer to? Now imagine you had to answer using only a short summary that you rewrote after each word. Which words would you expect that summary to keep most clearly?

What is left on the note

Each word that was read, with the share of it that is still on the note.

Two candidates for it

it stands for a thing, so the candidates are the two nouns, animal and street. No other word in the sentence can be what it refers to.

The note is one fixed size
The note stays the same size however long the sentence is. A short sentence fits comfortably. A paragraph does not, and nothing tells you which parts were squeezed out.

A network that works this way is called recurrent. The same small step is applied over and over. Each time, it takes the previous note and the next word and produces a new note.
Two problems Distance. Early words fade, so anything that depends on a connection across a long gap is lost.

Order. Word fifty cannot be read until word forty-nine has been read. Training could not be spread across many machines, which limited how much text anyone could train on.
One fix for both problems Stop summarizing. Keep every word, and let each word look directly at all the others, weighing them by how well they fit. Every word is then one step from every other word, and all the comparisons can happen at once.

This approach is covered later in "Attention and transformers".

Attention and the transformer

In a busy group chat, a reply such as "yes, that one" only makes sense if you look back at the earlier messages and decide which ones it answers. Attention works the same way. Each word in a sentence looks at the other words and decides which ones matter for it. In a transformer, every word does this to every other word at the same time.

A transformer is a model built around attention, and it is the T in GPT, which stands for Generative Pre-trained Transformer. "Recurrent networks" showed the problem: one note, rewritten after each word, and animal had faded by the time the sentence needed it. Attention keeps every word and lets each one look at all the others directly.

Think first. In the sentence The animal didn't cross the street because it was too tired, what does it refer to? Now change the last word to wide. What does it refer to now? Write down what you looked at in the sentence to decide.

The context window

A classroom whiteboard has room for a fixed number of lines. When it is full, someone erases the oldest line to make space for a new one. A language model's context window works like that whiteboard. On the whiteboard a person decides what to erase. In the model, the oldest text usually goes first, without any warning.

The context window is the amount of text, counted in tokens (see "Tokens"), that the model can see when it writes a reply. The system prompt, which is the standing instructions an app gives the model, the files you pasted, every turn of the conversation and the reply being written all share the same window. The model only sees what fits.

Tool calls and the Model Context Protocol (MCP)

At a barangay hall, you do not walk into the records room yourself. You hand a request slip to the clerk at the front desk, and the clerk decides whether to fetch the record, ask for an ID or turn you down.

A language model that uses tools works the same way. It does not run anything. It writes a tool call, which is a request in plain text, and a separate program decides whether to carry it out. This matters when you let an agent work on your files or database. An agent is a model that uses tools in a loop, as in "AI agents".

Two words change meaning in this panel. A server here is a small program that offers tools. The Module 1 site uses the word for a different thing, in "What a server is". A client is the part of your AI application that calls the tools.

Why there is a standard for tools

Phone chargers used to differ by brand, so every phone needed its own cable. A shared plug solved that. AI applications have the same problem. Each one needs to reach the same systems: your files, your database, your issue tracker, your calendar. Without a common format, every pairing of application and system needs its own adapter, which is a piece of code that connects the two. The number of adapters multiplies.

One adapter per pairing
One shared standard

MCP, the Model Context Protocol, is a published standard that anyone can implement. Anthropic released it in November 2024 and other vendors adopted it. An MCP server is a small program that wraps one system and lists what it offers. An MCP client sits inside the application you are using. It asks the server for that list and passes the model's calls on. Write the server once and any client that follows the protocol can use it.

What MCP gives you A place to approve or refuse. Every call passes through the client before it reaches anything real, so approval, logging and refusal each have a place to happen.

A list you control. The model can only ask for tools it was offered. If it says it cannot read your file, the usual reason is that nobody gave it a tool that reads files.

Portability. The same server works in whichever editor or agent you move to next.

What it does not give you: judgment. A tool that deletes rows will delete rows whenever it is called correctly. MCP delivers the request. Deciding whether the request should have been made stays with you, and in an agent loop requests can arrive faster than you can read them.

Writing better prompts

If you tell a tricycle driver "somewhere near the market," you could be dropped at any of a dozen places. If you say "the Loyola Heights gate on Katipunan," only one place fits.

A prompt works the same way. A prompt is the text you give a language model, and a constraint is a fact or limit you add to it. Each constraint rules out some of the answers the model might give. A driver can ask what you meant. The model picks one answer from the range that is left, as described in "Predicting the next word".

Think first. Suppose you ask a model for "a function to enroll a student in a course." How many different working answers could that describe? Which one do you expect the model to give you most often, and why?

System prompts and context A system prompt is text placed ahead of every conversation. It holds the rules that are true every time: the framework you use, your house style, what the model must never do without asking. It is set once and applies to everything.

Context is what applies to one task: the table definitions, the file, an example. Both narrow the range of answers. A system prompt lasts for every conversation and context lasts for one task.
Why the most likely answer is wrong With nothing specified, the most likely answer reads the seat count, checks it, and then creates the row. It looks careful and most tutorials show it. It fails when two students click at the same moment, because both can read the same count before either one writes. This failure is called a race condition. You can see it in the Module 1 site, "Transactions", and later in "Checking AI-written code".

The model gives this answer because it is the most common pattern in the text it learned from, and nothing in your prompt ruled it out.

AI agents: the think, act and observe loop

Suppose you send an intern to the registrar's office to fix a student's record. The intern decides what to do, does it, looks at what happened, and decides what to do next.

A chat model only produces text and cannot run anything or check results. An agent is a model connected to tools, so it can act and see the outcome. Typical tools are a shell (a window where you type commands), a file system (the folders and files on a computer) and a test runner (a program that checks whether code still works). Four ways an agent loop goes wrong It does not know when to stop. The model stops when it predicts a special end-of-output token, the same way it predicts any other token. That can happen too early, or not at all.

The context window fills. Every thought, action and observation is added to it. After twenty steps your original instruction may no longer be in what the model can see. See "The context window".

Errors compound. A wrong observation at step three is treated as fact in every step after it. The model's confidence does not fade on its own.

Cost grows with each step. You pay per step, the context grows each time, and attention cost rises with the square of the context length. The twentieth step costs more than the first for the same work.

The math behind it: vectors, slopes and probabilities

Your grade in a course is a weighted sum. You multiply each score by its weight and add the results. That one operation is the main piece of math in language models. This panel covers three ideas that appear in every lecture and paper on the topic: the dot product, the slope and the probability distribution. Each is school arithmetic, and each connects to a screen you have already seen. The symbols in papers are shorthand for these steps.

Think first. Before you read on, write down what you think each of these means: a dot product, a slope, a probability distribution. Then compare your answers with the explanations below.
1 · Vectors and the dot product

Suppose a course grades exams at weight 0.6 and projects at weight 0.4, and you score 80 on exams and 90 on projects. Your grade is 80 × 0.6 + 90 × 0.4 = 84. You multiplied each pair of numbers and added the results to get one number. That is a dot product. A vector is a list of numbers, so your scores [80, 90] are a vector and the weights [0.6, 0.4] are another. Two numbers can mark a position on a page. Three hundred numbers mark a position in a space you cannot draw, which is where words are placed in "Vectors and similarity".

In the picture, vector a is fixed and you swing vector b. The dot product is large when the two arrows point the same way. It is zero at a right angle and negative when they point apart.

Where you have met it The attention weight in "Attention and transformers" is a dot product between what one word is asking for and what another word offers. The similarity score in "Vectors and similarity" is the same operation with the lengths divided out, which is called cosine similarity. A unit in "Neural networks" multiplies each input by a weight and adds the results, which is a dot product with a fixed number called a bias added at the end.

A matrix is a grid of numbers, which you can read as a stack of vectors. Multiplying by a matrix performs many dot products at once. This is the meaning of the notation Wx: W is the matrix of weights and x is the input vector.
2 · Slopes and derivatives

A car's speedometer tells you how fast your position is changing right now. A slope is the same idea for any curve: how fast the answer changes when you nudge the input. 3 · Probability distributions and loss

A weather forecast might say 60% rain, 30% cloudy and 10% clear. That is a distribution: a set of outcomes, each with a probability, adding up to 100%. The model's choice of next word in "Predicting the next word" is a distribution over words. A loss is one number that says how wrong the model was, given what turned out to be true.

Vibe coding and agentic coding

The two terms are often used as if they meant the same thing. They describe different ways of working.

Vibe coding

You describe what you want, take what the model returns, run it, and describe the next change. You judge it by whether it seems to work. The term comes from Andrej Karpathy, who described it as a fine way to build throwaway projects, where being wrong costs you a deleted folder.

Agentic coding

An agent has a shell (a window for typing commands), your repository (the folder holding your project's code) and your test suite (a set of automated checks that report pass or fail). It works in the loop described in "AI agents". It can run things, read failures and revise. It can do more, and it can do more damage without being asked, because it acts as well as suggests.

When a prototype ships Vibe coding is a reasonable way to find out whether an idea is worth building. It stops being reasonable when somebody depends on the result, and that moment usually arrives without an announcement. Few people decide to put unreviewed code into production. It gets there because the prototype worked, the demo went well, and nobody stopped to read it.
