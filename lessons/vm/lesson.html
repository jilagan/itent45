Virtualization and what the cloud means

A cloud server is a virtual machine. Running many of them on one physical machine is called virtualization.

A student team needs a server for its project app tonight. It opens a cloud provider's console, chooses a 2 GB server and presses Create. About a minute later the console shows a running server. The team logs in and installs its app.

Think first. A data center cannot install and wire a new computer in one minute. What did the team receive?
Students usually answer "a computer in a data center". Steer them to "a share of a computer, made by software". The next step shows how many shares fit on one machine.

Bare metal means a physical machine with no virtualization. One operating system controls all of it. The kernel is the core of the operating system, and it controls the hardware. The shell is the program you type commands into. If you buy a bigger machine, you own all of it, including the 80% you are not using at 3 a.m.

Virtualized: one machine, many guests
Hypervisor: divides the machine between the guests
Host operating system
Hardware: 256 GB RAM, 64 cores

Each guest has its own kernel, disk and network card as far as it can tell, but these are simulated. The host is the physical machine, and its hypervisor divides the hardware between the guests. The hypervisor can create or delete a guest in seconds.

Overselling memory

Providers often sell more memory than the host has, because guests are rarely all busy at the same time. The hypervisor keeps some memory for itself. Move the sliders until the total passes the host's memory to see what happens.

The server in Server memory is one of these guests.

In this simulation an autoscaler adds machines. An autoscaler is a program that watches the load and adds machines when they are needed. Load is measured in requests per second (rps). Lowering the boot time recovers some of the surge and never all of it, because a surge that arrives in one second ends before anything that has to react first. Three things help: capacity that is already running, a queue in front, and spreading out the arrival times. Spreading out the arrivals is the fix from Case study: enlistment.

Examples

An Amazon EC2 instance or a DigitalOcean Droplet is IaaS. You receive a virtual machine and still install the operating system updates yourself.

Railway and Supabase are PaaS. You push your code to them and they run everything under it.

The learning management system and a web email service are SaaS for the people who use them. Your project is a PaaS customer, and it is a SaaS provider to its own users.
