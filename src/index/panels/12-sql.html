Four statements, and one of them can ruin your afternoon

Panel 05 fired requests at a table through an API. This is the same table with the API taken away. Everything your Django code eventually does to the database is one of four statements, and the ORM exists so that you rarely type them. You should still be able to read them, because when something is slow or wrong, what you will be shown is SQL.

Ask the room. Which of these four is the one you can run twice and change nothing? Now: which one has no undo?

The correspondence is not a coincidence. REST was designed against this shape. The verbs line up because of it, and a resource-shaped API is easy to build over a relational database and awkward over anything else.

The WHERE clause is not optional, it only looks optional UPDATE courses SET slots = 0 is valid SQL. It runs, it succeeds, and it sets every course in the school to zero slots. The database will not ask whether you meant it, because you told it what you wanted and it has no way to know you were thinking about one row.

This is why people write SELECT first with the same WHERE, look at what comes back, and only then change the verb. Do that on anything you cannot restore, and do it on production even when you are certain.
