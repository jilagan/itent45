Tokens: how text is fed to a model

A child sounding out a long word reads it in pieces, such as con-ver-sa-tion. The pieces vary in length, and the child does not stop to look at each letter inside a piece. A language model reads text in pieces too: a whole word, part of a word, or a punctuation mark. These pieces are called tokens.

A program called a tokenizer cuts your text into tokens before the model sees anything, and each token is replaced by a number. The model works with those numbers and does not see the individual letters inside a token. The tokenizer chooses its pieces from text that turned up often in the material it was built from.

What this explains
Why it miscounts letters. The model receives strawberry as three chunks, and the letters inside each chunk are not separate pieces of input. It has to work out the spelling indirectly, which makes counting unreliable.

Why there is a size limit. The context window is the most text a model can handle at once. It is measured in tokens.

Why the bill looks the way it does. Providers charge per token, so the same sentence can cost different amounts in different languages.
Cost differs by language English averages about four characters per token because most of the text used to build the tokenizer was English. Filipino and Tagalog are split into more pieces, so the same meaning takes more tokens. It costs more to send and fills the context window sooner. The tokenizer was built mostly on English text, so Filipino costs more per message.
