Entities, attributes and instances

Think of a class list in a spreadsheet. The sheet is about students, each column holds one fact such as the ID number, and each row is one student.

A data model is a plan of what data a system keeps and how the pieces connect. It starts the same way, as a pile of nouns from a conversation with whoever wants the system. Each noun is one of three kinds. An entity is a kind of thing the organization keeps data about, such as Student. An attribute is a fact that describes an entity, such as an ID number. An instance is one particular example, such as Juan dela Cruz.

In the spreadsheet picture, the entity is the sheet, an attribute is a column and an instance is a row. Sort the ten terms below.

Think first. A class meets in SOM 407. Is Room an attribute of the class or an entity of its own? Write down your choice and one reason for it.
How to tell them apart
Entity: a person, place, object, event or concept the organization keeps data about. It has many examples, and each one can be told apart from the others.

Attribute: a property of an entity. It describes nothing on its own and only makes sense when it is attached to an entity.

Instance: one example of an entity, stored as a row of data. You store instances, and you do not draw a box for each one.
Events can be entities Student and Course are easy to spot. Enrollment is easy to miss, because it feels like something that happened and does not feel like a thing. It still has a date, a status and a grade, and none of those belong to the student or to the course. When two entities need facts that describe the pairing between them, the pairing is an entity. What this does to your tables is covered later in "Relationships".
