Server capacity: workers, queues and requests per second

A server can finish only so many requests per second. The limit depends on the number of workers and on the time each request takes.

A fast-food branch has a few cashiers and one line. Customers arrive whether or not a cashier is free, and each cashier serves one customer at a time. If customers arrive faster than the cashiers can serve them, the line keeps growing.

Think first. If four cashiers each need 200 milliseconds per customer, how many customers can they serve in one second?
The answer is 4 workers divided by 0.2 seconds, which is 20 requests per second. Watch for students who multiply the two numbers. Ask what they expect p95 latency to do when arrivals reach 30 per second.

Definitions

Latency is the time from a request arriving to its answer being finished. Utilization is the arrival rate divided by the most the workers can finish per second. When arrivals exceed that maximum, the queue grows, latency keeps rising and throughput stops increasing. The workers here are the same separate processes as in "Server memory". Several machines are covered in "Load balancers and scaling".

Every request that is being handled or waiting also uses RAM. When the machine runs out of RAM, the operating system stops processes. Extra workers then make things worse, because each one needs RAM too.
