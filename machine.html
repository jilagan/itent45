What the Machine Is Doing

This module explains how an AI language model works, from choosing one word to checking the code it writes. Each lesson is a few short steps: read the step, try the one thing it asks, then answer the check at the end.

AI, machine learning, deep learning and generative AI

Artificial intelligence, machine learning, deep learning and generative AI are often used as if they meant the same thing. Each one sits inside the one before it.

A calculator gives the right change because someone wrote the rules of arithmetic into it. A new cashier learns to spot a fake bill by handling thousands of bills, and nobody writes down the rule. Both are useful. The four terms describe which way a system was built.

Think first. A chess program beat the world champion in 1997. Is it artificial intelligence, and did it learn from its games? Decide, then check in the next step.
Ask for a show of hands on both questions before students open the chess example. Most will say yes to AI and split on learning. The rule-based case matters most for the rest of the module, because later lessons assume students can tell a learned model from a hand-written program.

Select a system in the list to see which circles it falls inside. Two of the eight are AI that does no machine learning at all.

Read the circles from the outside in.

Artificial intelligence

Any program that does something we would call intelligent. Most of it is hand-written rules.

Machine learning

Programs that work out their own rule from labeled data.

Deep learning

Machine learning with stacked layers that choose their own features from raw input.

Generative AI

Systems that produce new content, such as text, images or code.

More detail

Examples of each kind

Artificial intelligence: chess engines, route finding, scheduling. Machine learning: spam filters, credit scoring, recommendations. Deep learning: face recognition, speech to text, translation. Generative AI: language models, image models, coding assistants.

Labeled data and features

For a spam filter, labeled data is a million emails already marked spam or not spam. A feature is one measurement a person decides to feed the program, such as the number of links. Deep learning takes over the job of choosing features, so you give it the raw input, such as pixels or sound.

Generative AI and the other three

A spam filter gives one of two answers. A generative system writes out something that did not exist before.

AI is not new. The term dates from 1956, and much of what runs banks is hand-written rules. Today a product that says "AI" usually means generative AI. Ask which kind it is, because a wrong rule is wrong the same way every time, and a wrong model is wrong in ways that depend on its training examples.

You can now tell which kind of AI a product uses.

More detail

Most AI does not learn

A great deal of what runs your bank, your airline and your traffic lights is rules that people wrote. It works, and nobody markets it as AI any more. What changed recently is the small innermost circle in the diagram.

Where this module goes

The rest of the module is about the innermost circle. It covers what the model predicts, how it is trained, what it reads, and what happens when you give it tools.

How a language model writes: predicting the next word

A language model writes by choosing one word at a time. It repeats the same step for every word it adds.

When you type a message, your phone keyboard suggests the next word. It has not understood your message. It has learned which words usually follow the ones you typed. A language model works on the same idea at a much larger scale.

Think first. A model has read "The capital of France is". Does it give its top word about 30, 60 or 90 percent probability? You will check in the next step.
Collect guesses before students open the widget. Most pick 90 percent or more, and the widget shows 89 percent. The distinction between recalling a fact and continuing a pattern comes up again in the code example under "Try other prompts".

The model gives every candidate word a probability, then picks one. Press Pick one a few times. Then set the temperature to 0, press Do it ten times and compare the two tallies.

More detail

What temperature does

Temperature controls how far down the list the model is willing to reach. At 0 it takes the top word every time. At 1 it picks at random, in proportion to the percentages shown. Picking at random in proportion to the percentages is called sampling.

The top word can still be wrong

At temperature 0 the model takes the most likely word each time. If that top word is wrong, you get the same wrong answer every time you ask, worded the same way and equally confident. That is harder to spot than an answer that changes from run to run.

Try other prompts

The first two prompts are sentences. The third is the start of a line of Python code that looks up a user in a database, where the model has to choose between two database commands, get and filter. The fourth shows what a flat list of probabilities looks like.

A full answer is the same step repeated. The model adds the word it picked to the prompt and asks again, and it never goes back. A model that works this way is called generative. Press Next word and watch the list change each time.

You can now explain why a model writes one word at a time and why an error carries forward.

More detail

What changes in the loop

After the first word, the model reads its own output as part of the prompt. By the time the next word is chosen, the words it wrote are treated the same way as the words you wrote. A long answer of perhaps eight hundred words is built this way, one chosen word at a time. The model does not write a draft and revise it, and no separate step checks whether the sentence is true.

Why one early error can run through a whole answer

If the model picks a slightly wrong word early, every word after it is chosen to fit that word. The result reads smoothly to the end, because each word is chosen to be a likely continuation of the text before it.

Generative models and classifiers

In "Training and test data", the boundary answered a closed question: which side is this student on? The answer was one choice from a set that existed before the model ran, and nothing new was made. A program that sorts inputs into fixed categories like this is called a classifier.

The model in this lesson answers an open question. The set of possible answers is every sequence of words there is. A generative model's output can be fluent, new and wrong at the same time. A classifier can only be wrong in the ways its fixed set of answers allows.

Image generators work differently

Image generators mostly start from random dots, called noise, and remove the noise in steps until a picture is left. That process is different from predicting words, and it fails in different ways. What you learn here about words does not explain why a generated hand has six fingers.

Students tend to assume that one mechanism sits behind every AI tool. Say out loud that this lesson applies to language models only.

What this kind of model is called

A straight boundary fitted to labeled examples is called logistic regression. The name confuses many people, because regression usually means predicting a number, and this model predicts a category.

Linear regression draws a line through the points to predict a value, such as the mark a student will get from the hours studied. Logistic regression draws a line between the points to predict a group, such as pass or fail. On screen both are a line. The first answers "how much?" and the second answers "which group?". The later lessons use the second kind.

How a model becomes a boundary

Nobody writes the line down. It starts in a poor position and is adjusted until it makes fewer mistakes. Adjusting a model to match examples is called fitting it, and the final line is the model.

Split the data before fitting, and only once. If you look at the test set, adjust something and test again, you have trained on it. That mistake is called leakage.

Data the model sees while it is fitted. A good score here means little.

More detail

Why a good training score means little

A model that has seen every answer can remember them, and from the inside remembering looks the same as learning. Every adjustment is made to reduce mistakes on the training examples, so a good score there is expected.

Why leakage is easy to miss

People make this mistake often without noticing, and results that looked strong during development then fall apart in front of real users. Information from the test set leaks into the model, which is where the name comes from.

Reading the gap

A small gap between the two scores means the model found the general shape of the data. A large gap means it memorized its examples. The bent line in "Fit a line and test it" shows this directly. A test set is commonly 20 to 30 percent of the data.

Training: adjusting a model to reduce its errors

Training repeats one routine: measure how wrong the line is, nudge it, and measure again. This lesson shows how the line is found and what the size of each nudge does.

Suppose you are standing on a hillside in thick fog and want to reach the bottom. You can feel which way the ground slopes under your feet. So you step downhill, feel the slope again and repeat.

Think first. Each step downhill has a size. What goes wrong if every step is very large? What goes wrong if every step is very small? You will test both next.

Press Run 200 and watch the loss fall as the line settles. Then move the step size, also called the learning rate, to its largest setting, press Reset and run 200 steps again.

More detail

Choosing the learning rate

The learning rate is the size of each step, and somebody has to choose it. If it is too small, training crawls, and you pay for computing power that is barely moving the line. If it is too large, the line jumps past the bottom and ends up on the other side, over and over, and the loss goes up when it should go down.

Nothing detects this for you. It is the most common reason a training run produces nothing, and it is the setting beginners change most often.

The line you just moved has three numbers. A weight sets how much hours studied counts, another weight does the same for attendance, and the bias shifts the line. Each step nudges all three to lower the loss. Nobody writes the final line down.

You can now explain how a model finds its numbers by repeated nudging.

More detail

The terms on this screen

Loss is one score for how wrong the line is across all of the students. Lower is better. Cross-entropy is the formula that produces the loss, and it gives a large penalty when the model is confident and wrong. Gradient descent is the routine of working out the slope of the loss for each of the three numbers and moving each one a small step downhill.

Scale

A large language model does the same kind of adjusting to hundreds of billions of numbers, for months, on thousands of machines. The arithmetic is similar, and the cost is far larger.

Where the line came from

The lesson "Training data and test data" used a boundary line without showing where it came from. This is how that line is found. The two students the line still gets wrong are the same two as there, and no straight line can catch them. The fix is covered in "Neural networks".

Neural networks: combining several lines

A neural network combines several simple cuts into one decision. This lesson uses students who drop a course, a case where no single straight line works.

Suppose a scholarship committee has several members. Each applies one simple cut-off, such as at least 10 hours of study a week or at least 70 percent attendance. The committee accepts a student only when every member agrees. Together the cut-offs describe a shape that no single cut-off can.

More detail

The diagram and the plot

Most people meet neural networks as a diagram of circles and arrows. The diagram shows the wiring, meaning which number is multiplied by which weight and passed on to where. The plot shows the effect, meaning what that wiring does to the space of possible students. Both are correct, and seeing only the diagram can make a network look more mysterious than it is.

How the layers combine

A unit is one line. A layer is a set of units. A deeper network has more layers, and each layer works on the answers of the layer before it. Nobody draws the shape on the plot by hand. Training moves each line until the combined shape makes fewer mistakes.

Why the nonlinearity matters

With the nonlinearity off, a layer can only add its units together, and a sum of straight lines is another straight line. A deeper network without a nonlinearity gains nothing, because eight units build the same kind of line as two. That small step between the layers is the reason any of this works.

When more units stop helping

Pushing the slider higher stops helping once the plot is separated. Extra capacity that you do not need is how you get the bent line in "Training data and test data".

Each straight line is a unit. The set of units is a layer, and the output unit says "stays" only when every line agrees. The layer is called a hidden layer because nobody shows you what its units decided. Training moved their lines.

More detail

Where the terms come from

One line fitted to data is logistic regression, which the lesson "Training data and test data" covered. Once you use several lines and combine their answers, you have a neural network with one hidden layer. A unit is sometimes called a neuron.

Units on the plot

One circle in the middle row of the diagram is one line on the plot. The weights on the two arrows entering a circle set that line's angle, and its bias sets how far from the center it sits. That is three numbers for each unit, as in "How training works".

Deeper networks

Deeper networks repeat the same idea. Each layer works on what the previous layer found, so the shapes become more elaborate while every piece is still a straight cut. A language model does this with billions of numbers. Attention, covered in "Attention and transformers", is one particular kind of layer.

The features are the measurements a model works from, such as hours studied. The two eras differ in who chooses them.

Before deep learning

A person picks the features, so a wrong one can be pointed at.

After deep learning

Early layers work out their own features from raw input.

The cost: a real model has billions of numbers and none means anything alone, so an accurate model can be impossible to explain.

More detail

Before deep learning

To spot a likely dropout, an analyst would decide what to measure: hours studied, attendance, or whether the student had missed two submissions in a row. Getting those right was the main job, and it needed someone who knew the subject area.

After deep learning

You give the network raw input and enough units, and its early layers work out their own features. In an image model, the first layers end up finding edges, later layers find shapes, and later still layers find faces. Nobody told the network to look for edges.

The cost: nobody can say what each unit means

The few numbers on this screen can still be read. A real model has billions of numbers, and when it goes wrong there is often nothing to point at. The same property that lets a model find features nobody named also lets it pick up patterns nobody intended. The lesson "Word embeddings" returns to where meaning comes from.

Backpropagation

A network has to find out how much each of its weights contributed to a wrong answer. Backpropagation does this by tracing the error backward through the network.

Suppose a dish is sent back to the kitchen because it is too salty. Several people handled it before it reached the customer. To decide who should change what they do, you start from the complaint and work backward through each person, asking how much that person's work affected the result.

Think first. Suppose the sauce station uses a little less salt. How much would the complaint change? What would you need to know about the steps after the sauce station?

A slope tells a weight which way to move. Press Step to run the network forward, then follow the blame backward until every weight has a slope. Play runs all the steps.

What is happening
More detail

What the name means

In the forward pass, each layer hands its answer to the next layer. In the backward pass, each layer hands its share of the blame to the layer behind it. Backpropagation means propagating, or passing along, the error backward.

The chain rule

The rule underneath is called the chain rule. You can use the idea without the formula: to know how much a weight mattered, multiply how much its output mattered by how much the weight affected that output.

Why a middle weight needs the layers after it

In "How training works", each of the three numbers touched the answer directly, so finding its slope took one step of arithmetic. With hidden units that shortcut stops working, because a weight in the middle affects the answer only through the units after it.

Each number on the trace is built from a number already worked out one step earlier, so nothing is computed twice. Backpropagation gets every slope in one backward pass, which costs about the same as one forward pass. Nudging each weight and rerunning the network would need a run per weight, a billion for a real model.

You can now say why training a large network is feasible.

More detail

History

The idea was published in 1986 and the arithmetic has not changed since. Hardware improved later, and then the amount of text available to train on grew.

What you can skip

You can skip the derivation, the notation and the proof that the method is correct. You will not implement this, because every machine learning library does it for you. One common cause of a training run that produces nothing is that the blame stopped flowing backward somewhere, and people describe that problem in these words.

A language model reads text as short pieces called tokens. This lesson shows how sentences are cut up and what that means for accuracy and cost.

A child sounding out a long word reads it in pieces, such as con-ver-sa-tion. The pieces vary in length, and the child does not look at each letter inside a piece. A language model reads text in pieces too: a whole word, part of a word or a punctuation mark.

How the pieces are chosen

The tokenizer chooses its pieces from text that turned up often in the material it was built from. Each token is then replaced by a number, and the model works with those numbers. It does not see the individual letters inside a token.

The model cannot see inside a token, so counting letters is unreliable. The context window is measured in tokens. Providers charge per token, so the same sentence costs more in a language that the tokenizer splits into more pieces, such as Filipino.

More detail

Why it miscounts letters

The model receives strawberry as three chunks, and the letters inside each chunk are not separate pieces of input. It has to work out the spelling indirectly, which makes counting unreliable.

Cost differs by language

English averages about four characters per token because most of the text used to build the tokenizer was English. Filipino and Tagalog are split into more pieces, so the same meaning takes more tokens. It costs more to send and fills the context window sooner.

Vectors and similarity of meaning

A vector places a word on a map. Words used in similar ways get nearby positions, so closeness on the map stands for closeness in meaning.

The rule that is often left out

Why the bias example is disputed

A 2016 paper by Bolukbasi and colleagues reported the programmer analogy using word2vec trained on Google News, and it became a standard illustration of bias in embeddings. Nissim and colleagues showed in 2020 that the analogy method produces part of the result. The search must exclude the input words, so it has to return something other than programmer, and a gendered-looking answer is partly a product of that rule.

What holds up is smaller. An embedding is built from a corpus, and patterns in that corpus become geometry. A prompt cannot remove that, because it is built into the positions the model uses. Anyone who claims one tidy number for how biased a model is should be asked how it was measured.

One vector per use of a word

On this map, bank would get one point, somewhere between the river and the money. Newer models give a word a different vector depending on the sentence around it. That change is a main reason retrieval works as well as it does today.

Both statements hold, and students tend to keep only one of them: embeddings do absorb the statistics of their corpus, and the famous analogies overstate how cleanly that shows up.

What the score is

The score is the cosine of the angle between the two arrows. It is 1 when the arrows point the same way and 0 when they are at right angles. It measures direction only, so a long sentence and a short one can score highly when they are about the same thing.

Recurrent networks: the approach before transformers

A recurrent network reads one word at a time and keeps one small note about everything read so far. Until about 2017, language models worked this way.

Imagine sitting through a long lecture with a single sticky note. After each sentence you rewrite the note to summarize everything so far, and then you forget the sentence. At the end you can answer questions only from the note. The model's note is called its hidden state.

The note is one fixed size

The note stays the same size however long the sentence is. A short sentence fits comfortably. A paragraph does not, and nothing tells you which parts were squeezed out.

Why the network is called recurrent

The same small step is applied over and over. Each time, it takes the previous note and the next word and produces a new note.

Why the answer is street

The two candidates for it are the nouns animal and street, because it stands for a thing. The note holds street more strongly in both sentences, so the model answers street whichever last word it read.

Distance. Early words fade, so anything that depends on a connection across a long gap is lost. Order. Word fifty cannot be read until word forty-nine has been read, so training cannot be spread across many machines. A fifty-page contract shows both problems.

More detail

One fix for both problems

Keep every word, and let each word look directly at all the others, weighing them by how well they fit. Every word is then one step from every other word, and all the comparisons can happen at once. This approach is covered in "Attention and transformers".

Attention and the transformer

Attention lets each word in a sentence look at the other words and decide which ones matter. A transformer is a model built around this idea.

In a busy group chat, a reply such as "yes, that one" only makes sense if you look back and decide which earlier message it answers. Attention works the same way. Each word looks back at the other words and decides which ones matter for it.

Think first. In The animal didn't cross the street because it was too tired, what does it refer to? Change tired to wide. Does the answer change?
Ask students what they looked at in the sentence to decide. The answer in both cases is the last word, and the widget shows the model doing the same thing.

Tool calls and the Model Context Protocol (MCP)

A language model cannot run anything. It writes a request in text, and a separate program decides whether to carry it out.

At a barangay hall, you hand a request slip to the clerk at the front desk. The clerk decides whether to fetch the record from the records room, ask for an ID or turn you down. You never enter the records room yourself. A language model that uses tools works the same way.

Think first. A model produces only text. Between your question and the database, where could a person or a program stop a harmful request?

What the model was given

This box is a tool description written in JSON, a plain-text format for structured data. It has a name, a one-sentence description and the shape of the input the tool accepts, called its schema. SQL is the language used to read and change database tables.

This is everything the model knows about the tool. It has never seen your tables, your rows or your server. It chooses a tool by reading the description, so a vague description leads to the wrong tool being called. That is a bug in the description, and the model is working as designed.

The risky statement

The delete statement has no WHERE clause, which limits a statement to certain rows, so it applies to every row. This is the missing WHERE clause from the Module 1 site, "SQL basics", this time sent by an agent and carried out in a moment.

Standing rules

In a loop of twenty steps, requests can go past faster than you can read them. So people set standing rules and stop reading every call. Typical rules are read-only tools by default, approval required for writes, and destructive statements refused.

Phone chargers once differed by brand. AI applications had the same problem: each needed its own adapter for every system it reached. The Model Context Protocol (MCP) is a shared standard, so each side is built once. MCP delivers requests and does not decide whether to make one. Compare the counts.

More detail

Server and client in MCP

An MCP server is a small program that wraps one system and lists what it offers. An MCP client sits inside the application you are using. It asks the server for that list and passes the model's calls on. Write the server once and any client that follows the protocol can use it. The Module 1 site uses the word "server" for a different thing, in "What a server is".

Where MCP came from

MCP is a published standard that anyone can implement. Anthropic released it in November 2024 and other vendors adopted it.

What MCP gives you

Every call passes through the client before it reaches anything real, so approval, logging and refusal each have a place to happen. The model can only ask for tools it was offered, so if it says it cannot read your file, the usual reason is that nobody gave it a tool that reads files. The same server works in whichever editor or agent you move to next.

What it does not give you

A tool that deletes rows will delete rows whenever it is called correctly. Deciding whether the request should have been made stays with you, and in an agent loop requests can arrive faster than you can read them.

Writing better prompts

A prompt is the text you give a language model. Each fact you add rules out some of the answers it might give.

Tell a tricycle driver "somewhere near the market" and you could be dropped at any of a dozen places. Say "the Loyola Heights gate on Katipunan" and only one place fits. A prompt works the same way. Every fact you add rules out some of the answers the model might give.

Think first. A model is asked for "a function to enroll a student in a course." Which kind of answer will it give most often, and why?
Let students commit to a guess before they open the widget. Most guess the careful-looking answer that checks the seat count first. Ask them what happens when two students click at the same moment.

    System prompts and context

    A system prompt is text placed ahead of every conversation. It holds rules that are true every time, such as the framework you use, your house style and what the model must never do without asking. Context is what applies to one task: the table definitions, the file, an example. Both narrow the range of answers.

    Why the most likely answer is wrong

    With nothing specified, the most likely answer reads the seat count, checks it and then creates the row. Both of two simultaneous requests can read the same count before either one writes. The model gives this answer because it is the most common pattern in the text it learned from, and nothing in the prompt ruled it out.

    AI agents: the think, act and observe loop

    An agent is a language model connected to tools. It thinks, acts and checks the result, then repeats.

    Suppose you send an intern to the registrar's office to fix a student's record. The intern decides what to do, does it, looks at what happened, and decides what to do next. A chat model can only produce text. An agent is a model that can also act and see the result.

    Think first. Of thinking, acting and looking at the result, which could a model that only produces text never do by itself, and why?
    Students usually say the model cannot act. Push for the second half: it also cannot know what happened without a result from outside itself.

    The agent is asked to fix a bug: some students are enrolled in the same course twice. Press Step to add one line at a time. Thought and Action lines come from the model. Observation lines come from a tool, such as a test runner. The task is done at step 15, so watch what happens next.

    A shell is a window where you type commands. A file system is the folders and files on a computer. A test runner checks whether code still works. Observation lines can also come from an API, which is a way for one program to request something from another.

    Four things go wrong in long loops. The model may not stop when the task is done. The context window fills up and pushes out your first instruction. A wrong observation is treated as fact in every later step. Each step costs more than the one before.

    You can now name four ways an agent goes wrong and what a person should watch.

    More detail

    It does not know when to stop

    The model stops when it predicts a special end-of-output token, the same way it predicts any other token. That can happen too early, or not at all.

    The context window fills

    Every thought, action and observation is added to it. After twenty steps your original instruction may no longer be in what the model can see.

    Errors compound

    A wrong observation at step three is treated as fact in every step after it. The model's confidence does not fade on its own.

    Cost grows with each step

    You pay per step, the context grows each time, and attention cost rises with the square of the context length. The twentieth step costs more than the first for the same work.

    The task in the trace ends at step 15. At which step would you have stepped in? Module 3 covers how to decide.

    The math behind it: vectors, slopes and probabilities

    Three ideas from school arithmetic appear in every lecture on language models: a weighted sum, a slope and a probability distribution. Each connects to a screen you have already seen.

    Your grade in a course is a weighted sum. Exams count 0.6 and projects count 0.4. You score 80 on exams and 90 on projects, so your grade is 80 × 0.6 + 90 × 0.4 = 84. You multiplied each score by its weight and added the results.

    Think first. A course weights exams at 0.7 and projects at 0.3. You score 60 on exams and 100 on projects. What is your grade?
    The answer is 72. Students who answer 80 averaged the two scores and ignored the weights. Ask why 72 is closer to the exam score.

    Any list of numbers can be drawn as an arrow. Arrow a stays fixed and you swing arrow b. The dot product is a weighted sum of the two lists. Drag the slider and watch it change.

    Slope and derivative

    A car's speedometer tells you how fast your position is changing right now. A slope is the same idea for any curve. A derivative is the formal name for the slope at one point. The slope is negative on the left of the dip, positive on the right and zero at the bottom. To get downhill, move in the direction opposite to the slope.

    Gradient

    A gradient is the slope worked out for every number at once. With three numbers it is three slopes. With a billion numbers it is a billion slopes, and the arithmetic for each one is the same.

    Where you have met it

    The Step button in "How training works" does exactly this. It works out the slope for each of the three numbers, moves each one against its slope and repeats. The learning-rate slider sets how far each move goes.

    A weather forecast might say 60% rain, 30% cloudy and 10% clear. Those percentages are a probability distribution. A model's choice of next word is one too. Raise the probability of Paris and watch the other words shrink.

    The formula

    The formula is -log(p), where p is the probability given to the right answer and log is the logarithm function on a calculator. This loss is called cross-entropy. It rises steeply as the probability approaches zero.

    Where you have met it

    This is the number that falls in "How training works". Temperature, in "Predicting the next word", changes the shape of the distribution the model samples from. The loss measures how much probability sits on the right answer.

    Why reading is not enough

    Reading the code does not reveal an N+1 problem, because it only shows up with a number of rows the model never saw. A race condition is only correct when nobody else is using the code. You cannot see either one by reading.

    Scale of the task

    With four short snippets, you knew each held exactly one defect. An agent will hand you three hundred lines and tell you the tests pass.

    More detail

    Where vibe coding comes from

    The term comes from Andrej Karpathy, who described it as a fine way to build throwaway projects, where being wrong costs you a deleted folder.

    What an agent has

    An agent has a shell (a window for typing commands), your repository (the folder holding your project's code) and your test suite (a set of automated checks that report pass or fail). It works in the loop described in "AI agents". It can run things, read failures and revise. It can do more, and it can do more damage without being asked.

    When a prototype ships

    Vibe coding is a reasonable way to find out whether an idea is worth building. It stops being reasonable when somebody depends on the result, and that moment usually arrives without an announcement. The prototype worked, the demo went well, and nobody stopped to read it. In Module 3 you practice finding that point on purpose.
