AI agents: the think, act and observe loop

Suppose you send an intern to the registrar's office to fix a student's record. The intern decides what to do, does it, looks at what happened, and decides what to do next.

A chat model only produces text and cannot run anything or check results. An agent is a model connected to tools, so it can act and see the outcome. Typical tools are a shell (a window where you type commands), a file system (the folders and files on a computer) and a test runner (a program that checks whether code still works). An agent repeats three steps: think, act, observe.

Thought and Action lines come from the model. Observation lines come from outside the model: a test runner, a file system, or an API (a way for one program to request something from another). They are the only lines that can contradict the model.

"Context in use" is how much of the model's context window the conversation has filled. The context window is the amount of text the model can see at once. See "The context window".

This pattern is called ReAct, short for reason and act.
What to watch for The task is finished at step 15. Watch what the agent does next, and ask whether you would have caught it in review.
Four ways an agent loop goes wrong It does not know when to stop. The model stops when it predicts a special end-of-output token, the same way it predicts any other token. That can happen too early, or not at all.

The context window fills. Every thought, action and observation is added to it. After twenty steps your original instruction may no longer be in what the model can see. See "The context window".

Errors compound. A wrong observation at step three is treated as fact in every step after it. The model's confidence does not fade on its own.

Cost grows with each step. You pay per step, the context grows each time, and attention cost rises with the square of the context length. The twentieth step costs more than the first for the same work.
