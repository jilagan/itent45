Entities, attributes and instances

A data model lists the nouns a system keeps data about. Each noun is an entity, an attribute or an instance.

You open the university's online enlistment system. The screen shows your name and ID number, then your courses. Each course has a code, a title, units, a section and a room such as SOM 407. You search for another course and press Enlist.

Think first. Each class shows a room such as SOM 407: is Room an attribute of the class or an entity of its own, and why?

How to tell them apart

Entity: a person, place, object, event or concept the organization keeps data about. It has many examples, and each one can be told apart from the others.

Attribute: a property of an entity. It describes nothing on its own and only makes sense when it is attached to an entity.

Instance: one example of an entity, stored as a row of data. You store instances, and you do not draw a box for each one.

Room: attribute or entity?

If a room is only a name such as SOM 407, it is an attribute of the class. If the school also records its capacity or whether it has a projector, or lists everything scheduled in one room, Room is an entity of its own.

Student and Course are easy to spot. Enlistment is easy to miss, because it is an event: a student signing up for a course. It has a date, a status and a grade, and none of those belong to the student or the course alone. So the pairing is an entity.
