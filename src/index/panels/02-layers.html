How network messages are layered (protocol layers)

Think of sending a parcel by LBC. You put your item in a box, the branch adds a waybill with the destination, and a hub may stick on a new label. Nobody opens the box until it reaches the receiver. A network message travels the same way, in layers. Each layer follows a protocol, which is an agreement about how a message is shaped. A layer wraps what it receives from the layer above in its own header (a block of labels at the front) and passes the result down. The receiving machine unwraps the layers in reverse order, and each layer reads only the header that its counterpart on the other machine wrote.

Think first The message in this topic is the 24-byte request GET /courses. Before you click anything, guess how many bytes of headers the layers add around it. Then click through the layers to check your guess.
The total is 121 bytes: 38 (HTTP) + 29 (TLS) + 20 (TCP) + 20 (IP) + 14 (Ethernet) around the 24-byte message, 145 bytes in all. Students find it by adding the header bars.

Click each layer to see what its header adds. The 24-byte request you wrote stays inside, unchanged.

What happens when a message does not fit in one packet

A network link cannot carry a message of any size. Ethernet carries about 1,500 bytes per frame, so a larger message is cut into pieces called packets, and every packet gets its own full set of headers. Drag the response size to see one reply become many packets.

Each packet carries up to 1,460 bytes of your data and 54 bytes of Ethernet, IP and TCP headers. Header overhead is the share of all bytes that are headers. A round trip is a message out and the reply back.

Press Send it to watch the packets leave. They do not all leave at once. TCP sends about ten, waits to hear that they arrived, then sends twice as many. A large reply therefore costs several round trips of waiting, in addition to the time the bytes take to move.
