21 — Module 4 · what "the cloud" actually is

Whose computer is it, actually?

Panel 17 treated your server as a physical machine with a fixed amount of RAM. That was a useful lie. The 2 GB box you rent is almost certainly a slice of a much larger machine, created in seconds by software, sitting alongside slices belonging to people you will never meet. That slicing is virtualization, and every property we call "cloud" follows from it.

Ask the room When you rent a 2 GB server, what did you rent? Nobody unwrapped a computer and put it on a shelf for you.

One operating system owns the whole machine. Buy a bigger box and you own all of it, including the 80% you are not using at 3 a.m.

Hardware  ·  256 GB RAM, 64 cores

Each guest believes it has its own kernel, its own disk and its own network card. None of that is true. The host and its hypervisor are dividing one real machine, and can create or destroy a guest in seconds, which is the whole trick.

Service models: the line moves, the work does not disappear

Every layer below still has to be run by somebody. Choosing a service model is choosing where you stop being that somebody, and paying them to be it instead.

LayerOn-premiseIaaSPaaSSaaS
you run it the provider runs it
In the terms from Module 1: a bare EC2 or Droplet is IaaS. You still patch the operating system. Railway and Supabase are PaaS. You push code and they run everything under it. your student portal, Canvas and Gmail are SaaS to the people using them. Your capstone is a PaaS tenant that is a SaaS provider to its own users.
