Lesson library

Short interactive lessons on computational thinking, software, data, the cloud and AI. Each lesson stands alone, so a course can use any of them in any order.

Courses that use these lessons:

  • Computational Thinking (CT)
  • Introduction to Computing for Technology Startups (ITENT 21)
  • Application Development and Emerging Technologies (ITENT 45)

Web applications

How a request travels from a browser to a server and back, and what the messages contain.

What is a server?

What a server is, and how to read a web address.

  • Say that "server" means a machine and a program, and any computer can be one
  • Read a URL as scheme, host, port, path
  • Say who can reach a laptop service (same machine, same wifi, outside) and why public hosting needs a rented box

Topics: server, client, URL, port, localhost

The three tiers of a web application

How a request travels from browser to server to database.

  • Name the three tiers and where each runs
  • Say why the browser cannot talk to the database directly
  • Follow a click through the 12 steps and name the tier doing each

Topics: three tiers, browser, application server, database

How network messages are layered (protocol layers)

How a message is wrapped in layers to cross the internet.

  • Explain encapsulation: each layer wraps the message and talks only to its twin
  • Estimate how much packaging a small message carries
  • Explain why a big reply becomes many packets and arrives whole

Topics: protocol layers, packets, TCP, headers

Why loading a page takes several round trips

Why distance and the number of round trips make pages slow.

  • List what happens before your code runs (lookup, connect, encrypt, request)
  • Predict wait time from distance and number of round trips
  • Say why more server capacity does not fix distance

Topics: latency, round trip, DNS, TLS

What an HTTP request and response look like

What an HTTP request and response look like, line by line.

  • Name the parts of an HTTP message (start line, headers, blank line, body)
  • Say what Host, 200, 201, 404 tell you
  • Send a request by hand to a local server

Topics: HTTP, request, response, headers, curl

HTTP verbs, URLs and status codes (REST)

Which request type to use, and how to read status codes.

  • Choose a verb for a task and say whether it is safe and idempotent
  • Read a status code by its first digit; separate 401 from 403 and 404 from 500
  • Judge endpoint design: noun URLs, one request or fifty, when fetching everything is waste

Topics: REST, HTTP verbs, status codes, idempotent, API

One API for the web, iOS and Android

How one API serves a website, an iPhone app and Android.

  • Say why one API can serve web, iOS and Android
  • Contrast a server that returns HTML with one that returns JSON
  • Classify a change as additive or breaking and say who breaks

Topics: API, JSON, mobile, versioning

Building the page: on the server or in the browser

Whether the server or the browser builds the page.

  • Compare server-rendered pages with single-page apps
  • Compare the size of JSON, XML and HTML for the same data
  • Choose one for a project and give a reason

Topics: server rendering, single-page app, JSON, XML

Online payments and payment gateways

How a card payment reaches a gateway without being charged twice.

  • Say which machines touch the card number and why the token exists
  • Explain a double charge and what the idempotency key does
  • Explain why a slow third-party call becomes your capacity problem

Topics: payments, gateway, idempotency key, tokens

Data and databases

How to describe data as tables, change it safely and choose a database.

Entities, attributes and instances

How to describe things and their details as tables.

  • Tell entity, attribute and instance apart
  • Decide when an attribute should become an entity (Room)
  • Recognize a pairing as an entity (Enrollment)

Topics: entity, attribute, instance, tables

Relationships: one-to-one, one-to-many, many-to-many

How rows in one table connect to rows in another.

  • Classify a relationship as 1:1, 1:M or M:N
  • Say which tables each needs (foreign key, or a third table)
  • Name facts that belong to the pairing

Topics: relationships, cardinality, foreign key, many-to-many

The REA pattern: resources, events and agents

A standard way to record sales, payments and who took part.

  • Find resource, event and agents in a transaction of your own
  • Explain why payment and enrollment are many-to-many
  • Say why a standard pattern shortens schema design

Topics: REA, resources, events, agents, schema

Reading and changing data with SQL

Read, add, change and delete rows with four short commands.

  • Read the four statements and map them to HTTP verbs
  • Predict what UPDATE or DELETE does without WHERE
  • Say which statements are safe to repeat

Topics: SQL, SELECT, UPDATE, WHERE

Transactions and two users changing the same data

What goes wrong when two users change the same data.

  • Explain how two sessions both book the last seat
  • Say which fix works (a lock or one statement) and why checking first fails
  • Say what atomicity, consistency, isolation and durability each guarantee

Topics: transactions, ACID, locks, concurrency

Normalization: storing each fact once

Why each fact should be stored in only one place.

  • Explain redundancy: one fact stored in many rows
  • Predict how many rows change on a rename
  • Say what goes wrong if you miss some

Topics: normalization, redundancy, tables

The N+1 query problem

Why asking for 50 records one by one is slow.

  • Define N+1
  • Estimate the query count for N rows under three approaches
  • Name the fix (join, select_related, caching)

Topics: N+1, queries, join, ORM

Choosing a relational or a document database

When to keep data in tables and when in documents.

  • Say that choosing relational or document depends on which questions you ask
  • Say where the schema is enforced in each
  • Choose one for a project and justify the choice

Topics: relational, document database, schema

Capacity and cloud

How much a server can handle, how to add machines and what the cloud costs.

How a server's memory is used

What uses a server's memory before any user arrives.

  • Work out how many workers fit in RAM after the operating system, web server and database
  • Explain process-per-worker and threads
  • Predict what moving the database to its own machine changes

Topics: memory, RAM, workers, capacity

Server capacity: workers, queues and requests per second

How workers and queues decide how many requests a server handles.

  • Compute maximum throughput from workers and handler time
  • Explain why past saturation latency climbs while throughput stays flat
  • Predict how RAM per request limits workers

Topics: capacity, queue, throughput, utilization

Scaling out with a load balancer

How a load balancer lets several machines share the traffic.

  • Distinguish scaling up from scaling out
  • Say what a load balancer does and what it needs from your code
  • Name the next bottleneck after a fix

Topics: scaling, load balancer, availability, bottleneck

Case study: enlistment day

One busy day that tests the capacity lessons together.

  • Separate read-heavy browsing from reserving, where every write must be correct
  • Explain why adding web servers does not fix one database
  • Name a fix that costs no hardware

Topics: case study, peak load, caching, database

Virtualization and what the cloud means

How one physical machine is split into many virtual ones.

  • Explain a VM as a slice of a host
  • Name the five NIST characteristics and tie three to things you did
  • Place IaaS, PaaS and SaaS by who runs what

Topics: virtual machines, cloud, IaaS, PaaS, SaaS

Cloud cost: capital expenditure and operating expenditure

Buying servers or renting them: what each costs and when.

  • Separate CapEx from OpEx
  • Explain the two ways to guess capacity wrong
  • List TCO items beyond price

Topics: CapEx, OpEx, TCO, capacity planning

Regions, availability zones and failover

What happens to your site when a data center fails.

  • Compute the minimum latency that physics allows for a distance
  • Match each failure type (machine, data center, region) to the setup that survives it
  • Choose a region for users and say why

Topics: regions, availability zones, failover, latency

Architecture

How to divide an application into parts and what each division costs.

One application or many services?

One application or many small services, and the cost of each.

  • Separate scaling out from splitting up
  • Compute memory with and without splitting
  • List what splitting costs (network calls, versioning, retries, tracing)

Topics: monolith, microservices, services, network calls

Language models and AI

AI, machine learning, deep learning and generative AI

How AI, machine learning, deep learning and generative AI differ.

  • Order AI, ML, deep learning and generative AI
  • Say a system can be AI without learning
  • Say what each term implies about how it fails

Topics: AI, machine learning, deep learning, generative AI

How a language model writes: predicting the next word

How a language model writes, one word at a time.

Training data and test data

Training: adjusting a model to reduce its errors

How a model improves by reducing its errors step by step.

  • Predict what a learning rate too high or too low does

Topics: training, loss, gradient descent, learning rate

Neural networks: combining several lines

How several simple rules combine to make a neural network.

  • Say what hidden units add and why the nonlinearity matters
  • State the trade: no hand-picked features, and no explanation of results

Topics: neural network, hidden units, nonlinearity

How a network works out which parts caused an error.

  • Say why a middle weight needs information from downstream

Topics: backpropagation, weights, gradient

Assemble a course

A course is one small file in courses/. It gives the course a title, an intro and groups of lesson ids, and it can set words such as the name of the final project. Run python3 build.py and the course gets a home page, a lesson list on every lesson page and a Next lesson button.

A lesson needs no course. Every lesson page opens by itself, and every lesson can go into Canvas from the embed page. A link to a lesson inside a course ends in ?c= and the course id. A link without it shows the lesson alone.

To write a new lesson, run python3 tools/new_lesson.py and read docs/AUTHORING.md.
