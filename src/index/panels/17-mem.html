How a server's memory is used

Think of a fast-food branch with a fixed floor area. The kitchen, the freezer and the stockroom take up space before the first cashier starts work, and every cashier you add needs a counter of their own.

A server has the same kind of budget. The space is its RAM (random access memory), the working memory for programs that are running right now. The operating system, nginx (a program that passes browser requests to your application) and Postgres (a database program) use some of it before your application starts. What is left is for workers. A worker is one running copy of your application that handles one request at a time, and each one uses more RAM than most students expect.

This panel counts how many workers fit in a given amount of RAM, and then moves the database to its own machine.

Think first. A laptop with 8 GB of RAM already has part of it in use before you open any program. Estimate how much is in use on your laptop right now. Then estimate the same for a server with 2 GB. Check both estimates against the memory bar below.
Open Task Manager (Windows) or Activity Monitor (Mac) to show the real figure for the laptop. Students usually guess close to zero. Then ask them to compare their server estimate with the bar at the default setting.
Memory budget

What one worker is

Django is a Python framework for building web applications. A common way to run a Django application is gunicorn, a program that starts several workers. The command gunicorn --workers 8 starts eight separate processes. A process is a running program with its own private memory. Each worker loads its own Python interpreter, its own copy of Django and its own copy of every library the code imports. The pandas data library alone can use 100 MB before the first request arrives.

The RAM per worker setting is the number that decides how large the machine has to be. Each worker uses that memory whether or not anyone is visiting the site.

Threads use less memory but have a limit. A thread is a separate line of work inside one process. All the threads in a process share its memory, so twenty threads cost little extra. Python also has a rule called the global interpreter lock, which lets only one thread run Python code at a time. Threads therefore suit work that mostly waits, such as waiting for the database. Separate processes suit work that mostly computes.

What splitting changes
The application machine gets the database's memory back, so more workers fit. Postgres gets a whole machine, so it can keep frequently used data in memory and read less from disk. Both help.

Every query now crosses a network and no longer stays inside one machine. That adds about 0.4 ms to each query. At two queries per request, every request takes 0.8 ms longer.

The model charges ₱540 a month for each gigabyte of RAM. The bottom row, cost per request per second, shows whether the second machine pays for itself.
Reasons to separate the database The main reasons are operational. The database can be backed up, copied to a standby and restarted without touching the application. A runaway query cannot use up the application's memory. The two machines can be sized separately. Speed is a weaker reason, as the cost row shows.
