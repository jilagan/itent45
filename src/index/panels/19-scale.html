Scaling out with a load balancer

When the line at a fast-food branch grows longer than its counters can handle, the owner can rebuild the branch with more counters or open more branches. With several branches, a guard at the entrance points each customer to a counter that is open and not too busy.

A server system faces the same choice. In "Server capacity" one machine reached its maximum. A bigger machine is called scaling up (vertical scaling). Several identical machines are called scaling out (horizontal scaling), and they need a load balancer, a program that receives every request and passes each one to one of the machines.

This panel compares the two options and shows how removing one bottleneck exposes the next.

Think first. Your site runs on two machines, and each can serve 80 requests per second. Users type only one web address. What has to happen between a user's browser and the two machines so that every request reaches one of them?
Students should arrive at one address that answers for all the machines, which is the load balancer. The browser never learns how many machines there are. Ask what happens if that single address itself fails.

There are two ways to get more capacity, and they have different costs.

Option 1: scale up (vertical)

Buy a bigger machine

Add more RAM and more processor cores to the single machine. "Server memory" covers the memory side. This needs no code changes, so it is the first thing to try.

There is a limit. The largest machine you can rent has a fixed size, and the price rises faster than the capacity. One machine is also a single point of failure: if it breaks, the whole site is down.
Option 2: scale out (horizontal)

Run several copies of the machine

These are identical copies of the machine from "Server capacity", with a load balancer in front deciding which copy gets each request. There is no fixed upper limit, and one machine failing no longer takes the site down.

Your application has to meet one condition. Every copy must be able to answer any request, because you no longer control which copy receives it.
What a load balancer does

A load balancer is a reverse proxy. It has one public address, accepts each connection from a client and opens a second connection to one of the backends, which are the machines behind it. Clients never see the backends. Every few seconds it also sends each backend a health check, which is a small request to see whether the backend answers. It stops sending work to any backend that does not answer.

Finding the next bottleneck

The system below receives 400 requests per second (rps). A bottleneck is the part of the system with the lowest capacity, and it sets the limit for the whole system. Each fix below removes one bottleneck and shows you the next one. The application machines are copies of the machine in "Server capacity". A cache is a fast store that keeps recent answers, so the database is asked less often. A read replica is a copy of the database that answers read-only queries. A queue of background jobs lets a request finish before slow work, such as sending an email, is done. The database is measured in queries per second (qps).
