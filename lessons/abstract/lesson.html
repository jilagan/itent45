Abstraction and models

An abstraction keeps the details that matter for a question and hides the rest. A model built this way is easier to use than the real thing.

A jeepney route map shows stops and lines. It leaves out building shapes, traffic lights and the color of each jeepney. A commuter needs the order of stops and where lines cross. A picture that keeps only what a decision needs is an abstraction.

Think first. You are building an app that tells commuters which jeepney to ride. Name two details of a route to keep and two to leave out.
Typical keeps are stop names, the order of stops and the fare. Typical drops are the jeepney color and the buildings. Ask what the app would need if commuters also asked how long a ride takes.

A model is a simplified copy of something real. This one describes a jeepney trip from Katipunan to Cubao and starts with every detail switched on. Pick a question, then switch off each detail it does not need.

A model fits one question

Every model leaves something out, and it fails when the question changes. A route map has no distances, so it cannot say which route is faster.

Data representation

The same facts can be stored as a list, a table or a map. The choice decides which questions are easy to answer. A fare table answers cost questions at a glance and says nothing about the order of stops.

The same action can be described at different levels of detail. A level hides the steps below it, and each person needs the level that fits their job. Zoom in one level at a time, then press the person who works at the level shown.

Abstraction in software

A function name, a table design and an API are abstractions. A user of the API can ignore how the server stores data, as long as the interface stays the same.

A model works for the question it was built for. When the question changes, check whether the model still holds the details the new question needs.

You can now choose the details a model needs, check that it still answers the question and describe an action at the right level of detail.
