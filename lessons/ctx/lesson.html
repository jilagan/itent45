The context window

The context window is everything a model can see when it writes a reply. Text that does not fit is invisible to it.

A classroom whiteboard has room for a fixed number of lines. When it is full, someone erases the oldest line to make space for a new one. A model's context window works the same way, except the oldest text usually goes first and nothing warns you. The window is counted in tokens.

Think first. You have worked with an AI coding assistant for an hour, and it now ignores an instruction you gave at the start. What could explain this?
Students often say the assistant got tired or chose to ignore the instruction. Steer them toward what the model can still see.

The system prompt, your pasted files, the conversation and the reply all share one window. Raise Files you pasted past half the window, then raise Conversation so far, and watch what drops out.

Change the window size

Same budget idea as server memory

This works like the memory budget in Server memory. There, the operating system and other programs use part of the server's memory before your code starts. Here, the system prompt and whatever you paste use part of the window.

A model has no memory outside the window. When you open a new chat, the window starts empty, and the model knows nothing about the old chat unless the product copies text from it into the new window. Anything the model should know has to be in the window.

Long sessions with an agent

An agent session is one long conversation. The files it reads, the commands it runs and your messages all use the window, so a long session drifts when early instructions drop out.
