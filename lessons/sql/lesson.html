Reading and changing data with SQL

A database table works like one Excel sheet, and you can do four things to it. Each one has a command in a language called SQL.

In Excel you can filter rows, add a row, change a cell and delete a row. A database table does the same four things, and a command in SQL does each one.

Think first. Which of the four commands never changes the table, and which leave it in the same state when you run them twice?
Collect guesses before anyone opens the next step. Most students pick SELECT for the first question and are unsure about UPDATE and DELETE for the second.

Pick a statement and press Run. Then press Run a second time. A command that leaves the same end state when repeated is called idempotent. Try the two statements marked "no WHERE clause" last.

A WHERE clause says which rows a command affects. Without it, UPDATE and DELETE apply to every row. The database does not ask for confirmation, and there is no undo. Write a SELECT with the same WHERE first, check the rows it returns, and then change the command.

More detail

UPDATE courses SET slots = 0 is valid SQL. It runs without error and sets every course in the school to zero slots, because the database cannot know you were thinking about one row.

Follow the same habit on production, the live system that real users depend on, for any data you cannot restore, even when you are sure.

More detail

The table in this step is the same one used in HTTP verbs and status codes, this time with no API in front of it. An API that exposes resources is easy to build on top of a relational database.

Your Django code, a Python web framework, eventually turns into one of these four commands. A tool called an ORM (object-relational mapper) writes them for you, so you rarely type them. You should still be able to read them, because when something is slow or wrong, the logs show SQL.
