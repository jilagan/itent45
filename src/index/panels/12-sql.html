Reading and changing data with SQL

In Excel you can filter rows, add a row, change a cell and delete a row. A database does the same four things, and each has a command in a language called SQL. A table is like one sheet. SELECT reads rows, INSERT adds a row, UPDATE changes rows and DELETE removes rows. Your Django code, the Python web framework used in this course, eventually turns into one of these four commands. A tool called an ORM (object-relational mapper) writes them for you, so you rarely type them. You should still be able to read them, because when something is slow or wrong, the logs show SQL. The commands and the HTTP methods match because REST was designed around the same four operations. An API that exposes resources is easy to build on top of a relational database.

Always use WHERE with UPDATE and DELETE A WHERE clause is the part of a command that says which rows to affect. UPDATE courses SET slots = 0 is valid SQL. It runs without error and sets every course in the school to zero slots. The database does not ask whether you meant it, because it cannot know you were thinking about one row.

Before you change data, write a SELECT with the same WHERE, look at the rows it returns, and then change the command to UPDATE or DELETE. Do this for any data you cannot restore, and do it on production, the live system that real users depend on, even when you are sure.
