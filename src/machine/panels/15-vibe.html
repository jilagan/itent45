Finding mistakes in AI-written code

Imagine proofreading a receipt. Every word is spelled correctly and the layout is clean, but the total at the bottom is wrong. Checking the spelling will not find the problem. Code written by an AI model can be like that receipt. It reads cleanly and still does the wrong thing. You are about to watch an agent write code quickly. What to check Generated code almost always looks like correct Django. Check the things the model could not have known: what is in your tables, what runs twice, and what happens when two people click at the same moment.
Vibe coding and agentic coding

The two terms are often used as if they meant the same thing. They describe different ways of working.

Vibe coding

You describe what you want, take what the model returns, run it, and describe the next change. You judge it by whether it seems to work. The term comes from Andrej Karpathy, who described it as a fine way to build throwaway projects, where being wrong costs you a deleted folder.

Agentic coding

An agent has a shell (a window for typing commands), your repository (the folder holding your project's code) and your test suite (a set of automated checks that report pass or fail). It works in the loop described in "AI agents: the think, act and observe loop". It can run things, read failures and revise. It can do more, and it can do more damage without being asked, because it acts as well as suggests.

When a prototype ships Vibe coding is a reasonable way to find out whether an idea is worth building. It stops being reasonable when somebody depends on the result, and that moment usually arrives without an announcement. Few people decide to put unreviewed code into production. It gets there because the prototype worked, the demo went well, and nobody stopped to read it.
